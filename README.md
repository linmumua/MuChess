# MuChess

Paper 服务端的棋类对局插件。棋盘以 CraftEngine 家具的形式立在世界里，棋子是显示实体。中国象棋、五子棋、围棋共用同一套对局框架，只换规则实现。

| 棋种 | 棋盘 | 占位 | CE 家具 id |
|---|---|---|---|
| 中国象棋 | 9×10 交叉点 | 2x2 | `muchess:xiangqi_board` |
| 五子棋 | 15×15 | 2x2 | `muchess:gomoku_board` |
| 围棋 | 19×19 | 3x3 | `muchess:go_board` |

作者：linmumua

## 环境要求

| 项 | 要求 |
|---|---|
| 服务端 | Paper 26.1.2 或 26.2 |
| Java | 25（Paper 26.x 的硬要求） |
| CraftEngine | 编译依赖 26.7.4，可选。没装也能启动，棋盘和棋子退回原版外观。实测 26.8-SNAPSHOT 也能正常加载 |

## 构建

默认打 26.2：

```bash
./gradlew build
```

打 26.1.2：

```bash
./gradlew build -PchessTarget=paper-26.1.2
```

产物分目标落在 `build/<目标 id>/libs/MuChess-<版本>.jar`，版本号取 `build.gradle.kts` 里的 `version`。两个目标各自独立目录，来回切换不会覆盖。

`api-version` 跟着目标走（26.1.2 或 26.2），不是写死的。新增受支持版本时改 `build.gradle.kts` 里的 `supportedTargets`，paper-api 坐标、`api-version`、JDK 版本三样要一起给。

TabooLib 与 Kotlin 标准库不打包，首次启动时由 TabooLib 的 loader 联网下载到本地缓存。SnakeYAML 同理，走 `@RuntimeDependency`。所以构建产物里只有 26 个 TabooLib 引导类，`kotlin/` 与 `snakeyaml` 条目都是 0。**这意味着服务器首次启动需要能访问外网**，之后从缓存加载。

复核这几条约束：

```bash
python tools/jar-check.py build/paper-26.2/libs/MuChess-1.10.0.jar 26.2 1.10.0
```

它查六项：`kotlin/` 与 snakeyaml 为 0、引导类数在 20~40 之间、没有未重定位的 `taboolib/` 顶层包、`plugin.yml` 的版本与 `api-version` 与 `folia-supported`、`pack.yml` 版本跟随插件版本且作者是 linmumua。

引导类数查上限也查下限，是因为 TabooLib 被重定位到 `linmumua.taboolib.*`：按 `taboolib/` 前缀去数会得到 0，看着像"完全没打包"，其实是查漏了；而引导层真的缺失时插件根本起不来。

构建过程会顺带做两件事：

- `generateCraftEnginePack`：用 Java2D 画出象棋 14 种棋子、围棋与五子棋的黑白子、三块棋盘面的贴图（22 张 PNG），产出 CraftEngine 的 `pack.yml` 与 `configuration/` 配置，一共 120 个文件。完成后做像素自检，字形占比过低会让构建失败 —— 构建机器上没有中文字体时会在这里报出来，而不是产出一堆空白棋子。
- `fixPluginDescription`：把 TabooLib 写死的 `api-version: 1.13` 改成当前目标的版本号，`folia-supported: true` 改成 `false`。后者没在 Folia 上验证过，不声明。这一步带断言，上游改了字面量会让构建失败而不是静默失效。

## 安装

把 JAR 丢进 `plugins/`。启动后：

1. 插件检测 CraftEngine 是否在位。
2. 在位的话异步把资源包写进 `plugins/CraftEngine/resources/muchess/`，内容没变化时跳过。
3. 触发一次 CraftEngine 重载。重载完成的事件里才接管棋盘与棋子外观 —— CE 的物品注册表在 `onEnable` 阶段是空的，早了取不到东西。

关掉 `config.yml` 里的 `craftengine.auto-reload` 时需要自己执行 `/ce reload all`，插件会在控制台提示。

## 命令

棋盘没有放置命令。棋盘就是一个 CraftEngine 家具，拿 CE 的棋盘物品右键地面放下即得一副空棋盘，
物品用 CE 自己的给予命令取。放下不摆棋子，棋子等到有人点"开始"才铺上去。

入座与开局也没有命令，走世界内入口：棋盘上方有一行可点击的悬浮字，等人时显示"加入对局"，
双方坐满后翻成"开始对局"，点它才真正开局。shift+右键棋盘会开一个单按钮的箱子菜单，
按钮同样按状态在加入与开始之间切换，供关掉 `config.yml` 里 `board-label.enabled` 时使用。

| 命令 | 作用 |
|---|---|
| `/chess remove` | 收走附近的棋盘 |
| `/chess bot <add\|remove> [红\|黑]` | 加或撤机器人，不写边就挑空位 |
| `/chess pass` | 虚着（只有围棋支持）。双方连续虚着即终局数子 |
| `/chess leave` | 离座 |
| `/chess resign` | 认输，需要输两次确认 |
| `/chess reload` | 重载配置与语言文件 |
| `/chess pack` | 重新生成 CraftEngine 资源包 |

## 怎么下

象棋是"先选后走"：右键棋子选中，棋子浮起并放大，同时所有合法落点标出来 —— 空点是一圈半透明的白色 `ItemDisplay` 小圈，能吃的子直接给那枚棋子套红色描边，选中的己方棋子是橙色描边。合法落点用的是显示实体，不是原版粒子。再右键其中一个标记就走子或吃子。右键同一枚取消选中，右键自己另一枚直接换选中。

五子棋与围棋是"单击落子"：没有选中态，右键空交叉点直接下子。围棋提子时被提的显示实体成批删除。轮到自己却不想下时用 `/chess pass` 虚着，双方连续虚着即终局数子。

点了走不了的地方不会有任何提示。合法落点已经全部标出来了，点在标记之外就是不能走，再用文字复述一遍蹩马腿、塞象眼是同一件事说两遍，落子频率下一局能把聊天栏刷满。唯一保留的即时提示是将军，因为那是棋盘上看不出来的信息，而且它走动作栏不占聊天记录。

## 配置

所有人类可编辑文件都是 YAML，运行期只用 SnakeYAML 解析。

| 文件 | 职责 |
|---|---|
| `config.yml` | 开关、粒子与动画参数、CE 资源包生成、各棋种的规则可调项 |
| `lang/zh_CN.yml` | 玩家可见文案的唯一来源 |
| `boards.yml` | 已放置棋盘的运行时数据 |

棋种可调项在 `config.yml` 里各占一段：`gomoku`（禁手开关）、`go`（贴子、机器人候选上限）。围棋的 `bot-max-candidates` 单独一档而不是共用 `bot.max-candidates`，因为 19 路要更狠的裁剪，而调小共用值会连带削弱五子棋的防守；默认 12 有实测依据，注释里写了推算过程。

想换棋子美术资源，直接覆盖 `plugins/CraftEngine/resources/muchess/resourcepack/assets/muchess/textures/` 下的同名 PNG，然后 `/ce reload all`。注意 `/chess pack` 会按内容比对重新覆盖，改完自己的贴图后把 `craftengine.auto-generate-pack` 关掉。

## 象棋规则实现依据

规则按象棋百科全书（xqbase）与亚洲象棋规例实现，几处容易写错的地方：

- **蹩马腿**的阻挡点是起点沿"走 2 格那个轴"方向的第一格，不是起终点中点。所以马的走法是非对称的 —— A 能吃 B 不代表 B 能吃 A。
- **塞象眼**的阻挡点是起终点的中点。
- 两种阻挡都不分敌我。
- **炮**吃子必须跨过恰好一个子，跨 0 个或 2 个以上都不行，炮架不分敌我。
- **飞将**：把将视为車，能直接吃到对方将就算被将军。任何造成对脸的着法因此都是送将。
- **困毙判负**。未被将军但无子可走，判负，这点和国际象棋不同。
- 将军检测用反向探测：从己方将出发按車、炮、馬、过河兵的走法反查，不生成对方全部走法。反向探测马时马腿位置用士的偏移方向组。

长将、长捉这类裁判级判定没有实现，规范里明确把它列为独立可配置模块，没有混进走法生成器。自然限着（默认 60 回合无吃子判和）可以在 `config.yml` 里关。

## 测试

```bash
./gradlew test
```

451 个用例，0 跳过，两个目标各跑一遍。蹩马腿、塞象眼、飞将、送将、困毙各有独立用例；棋盘坐标换算有四种朝向 × 90 格点的往返一致性测试；走棋交互的"不出声"是被测试守住的 —— 语言文件里再出现 `move-illegal*` 这批键，或者 `MoveExecutor` 里重新出现 `Msg.send`，测试就会红。

另有两个机械检查，改完对应部分记得跑：

```bash
python tools/lang-check.py    # 代码引用的语言键 yml 是否都有
python tools/jar-check.py <jar> <api-version> <版本号>
```

`lang-check` 必须跟着 `config/Msg.kt` 的公开方法走。它漏掉 `component` / `actionBar` 时，悬浮字与将军提示那批键从来没被核对过，而缺键的表现只是静默不显示，构建和单测都发现不了。往 `Msg` 里加方法时同步改脚本里的 `METHODS`。

## 从 1.9.x 升到 1.10.0

围棋是新棋种，所以配置与 CE 资源都有新增项。直接替换 JAR 即可，不需要手工改档：

- `boards.yml` 老档没有 `game-type` 键，读出来按象棋处理，已放置的棋盘不会消失（`BoardRecordCodec` 有专门用例守这条）。棋种名写错也退象棋，不丢整条记录。
- `config.yml` 缺 `go` 段时全部走默认值（贴子 3.75、机器人候选上限 12）。想调就把新版模板里那段抄过去，注释里写了取值依据。
- CE 资源包新增 `muchess:go_board` 家具与它的棋盘面贴图，`/chess pack` 或重启时自动写入，之后需要一次 CE 重载（`craftengine.auto-reload` 开着就不用管）。棋子沿用五子棋那对 `black_stone` / `white_stone`，是同一份素色圆盘资源，只有显示尺寸不同。
- 语言文件删掉了 `bot-unsupported-go`（围棋现在支持机器人了）。自己改过 `lang/zh_CN.yml` 的话这个键留着无害，只是不再被引用。

不兼容的只有一处：1.9.x 给围棋棋盘加机器人会被拒绝并提示"还不支持"，1.10.0 起会真的加上。

## 已知限制

- **在线行为没有实机验证过。** CE 家具的实际放置效果、粒子渲染、右键命中精度都需要真实 Paper 服务端才能确认，当前环境没有。规则、坐标换算、文案映射这些能离线测的部分已经覆盖。
- 棋子贴图是程序化生成的，不是手绘美术资源。要好看得自己换图。
- CE 家具元素的旋转键在可查到的文档里没有，所以棋盘面的视觉由插件自己用 `ItemDisplay` 渲染，CE 家具只负责可交互占位（象棋与五子棋 2x2，围棋 3x3）。这三处坐标（构建期 hitbox、`BoardAnchor.origin`、`CraftEngineBoardVisual` 里的偏移）是联动的，改一处必须同时改另两处。
- 五子棋禁手（三三、四四、长连）默认关闭，是可配置项。
- **围棋规则是简化版**，两处与正式中国规则不同：终局不做死活判定（盘上没提干净的死子会被算成活子，所以双方应当自己把该提的提干净再连续虚着），也不做还棋头。劫只判单步同形（禁止立即提回），不判超级劫。劫与虚着计数不写进 `boards.yml`，重启后这两项归零，是显式取舍。
- **围棋机器人棋力很弱**，约等于刚学会规则的新手。它会提子、救被叫吃的块、不自杀、收官后停手；不会定式、死活、征子。另有两条是主动放弃的：它永不往已被单色围死的空区里打入（判断打入死活需要读棋，而数子口径下一颗死子会让对方整片围空作废、估值虚高上千，宁可不赚也不能乱送），也分不出"现在虚着是赢是输"——让它停手的判据不含胜负信息。
